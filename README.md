# Function Documentation
## Access token creation
Both main functions within this function app make use of the _getAccessToken() function. The _getAccessToken() function creates a bearer token by using the Microsoft Authentication Library (MSAL) and credentials from the App Registration in the Azure Tenant. These credentials are stored within the local.settings.json file and the environment variables on the Azure Function App resource.

## Querying SharePoint
Both main functions within this function app also make use of the _sharepointQuery() function. The _sharepointQuery() function takes the profile's unique URL and the access token generated by _getAccessToken() and sents an HTTP GET request to the URL with the access token as the Authorization header. It attempts to return the value labeled '@microsoft.graph.downloadUrl', and if an exception is thrown, the error is logged and can be found in Application Insights.The microsoft graph downloadUrl is used by the _tempSave() function as well as the export feature in the front-end. 

## Parsing functions
### Public functions
The main function for parsing is ProfileCreatedOrModified, which uses a Service Bus Trigger with a URL which can be called with an access token to retrieve a file from SharePoint. It has an output binding to a blob storage account, where it will output the parsed JSON object created from the profile for pickup by the next part of the data pipeline. The URL sent via the Service Bus message will be included in the parsed object as the 'sharepointRef', and is used as the profile's unqiue ID in the database. 

### Global values
REQUIRED_SECTIONS, BULLET_SECTIONS, and LONGFORM_SECTIONS: 
For easier parsing, these three values are set globally within the code. They are lists of strings, and are accessed throughout various functions during the parsing process. 
REQUIRED_SECTIONS is a list of all "sections" in the profile template. It matches the titles of the respective sections in capitialization, spelling, and spacing. 
BULLET_SECTIONS is a list of all the sections on the template which are formatted in bullet points. This allows these values to be stored and displayed in the front-end as separate values under the same section name. 
LONGFORM_SECTIONS is a list of all the sections on the template which may be in multiple chunks on the document but are all part of the same value. This allows these values to be stored and displayed in the front-end as the same value under the proper section name. 

### Private functions
_tempSave(): this function uses the tempfile library to find the temporary directory, downloads the profile to the temporary directory via the microsoft graph downloadUrl, and returns the path to the downloaded profile.

_get_file_type(): this function either returns the path to a PDF conversion of the profile or, if the file extension indicates that the file is not a Powerpoint file, an error is logged and can be found in Application Insights.

_convertToPdf(): This function uses the Spire library to convert the Powerpoint presentation to .pdf. If an exception is thrown, the error is logged and can be found in Application Insights.

_read_pdf_with_metadata(): this function uses the pymupdf library to break down the PDF document into chunks, and sort them into an array of value pairs like {"section":"text"}, where the section is set by finding words that are in the list of profile sections and the text is all the text that came after those words. If an exception is thrown, the error is logged and can be found in Application Insights. If no content is returned from this section, the main function will log an error that can be found in Application Insights and the transaction will be terminated.

_parse_profile(): this function makes use of several helper functions to complete the work of parsing the profile. It takes in the content which was return from _read_pdf_with_metadata(). Since on the current template the name, job title, and email are not or may not be preceded by their section name, the _extract_contact_information() function is run first to retrieve those values and remove them from the rest of the data for easier parsing. The parsing progresses by either concatentating all the text labelled by the same section name into one string or by appending each text value with the same section name into an array. These strings and arrays are stored in a dictonary structure with the section names as keys. Once this dictionary is completed, the values are stripped, delimited, split, and have bullet points removed by the _bullet_section_helper(), _longform_section_helper(), and _experience_section_helper() functions. The values and section names are then structured into a json-like object and returned.

_extract_contact_information(): this function handles the name, job title, and email values since they are not or may not be preceded by their section name. It uses regular expressions to look for a string that matches the header and a string that matches an email address, as well as a string that matches a watermark which is automatically inserted by the Spire library. The name, job title, and email values are returned if they are found and errors are thrown and logged if they are not found. This is because these 3 values are judged to be essential to have a meaningful profile entry. The watermark value is simply removed. The elements of content that contain the above values are fully removed from the content in this function, so that the values are not duplicated and erroneously included in the content of other sections.

## DownloadURL retrieval functions
The main function for downloadUrl retrieval is getURL. It is triggered by a HTTP POST request to its route. It is currently set to Authorization level Anonymous. It expects the HTTP POST request body to contain a URL that can be used to retrieve a document from Sharepoint - this is achieved by sending the sharepointRef attribute of a profile. It uses the _sharepointQuery() and _getAccessToken() functions to retrieve the document, and returns the microsoft graph downloadURL for export use.
